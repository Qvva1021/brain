# 文档 02：需求与范围（Requirements & Scope）

> 适用读者：理解了项目总览（文档 01）的初学者。本文件回答三件事：**第一版到底做什么？做到什么程度？怎么验收？**

本文档约定三个状态词，全文通用，务必统一：

| 状态词 | 含义 | 界面/文档上的展示要求 |
|---|---|---|
| **已实现** | 第一版真正编码并可以运行的功能 | 正常展示 |
| **占位（预留接口）** | 有入口、有接口签名，但未真正实现 | 必须标注「后续接入」「未实现」或「仅保留接口」 |
| **未来可扩展** | 只存在于方案设计里，第一版不出现任何入口 | 仅在文档中出现 |

## 2. 已实现 / 第一版实现 / 后续占位的边界

为了不误导老师与用户，用一句话划清边界：

> **第一版实现的是"一条从头到尾能跑的演示链路"；所有"真实能力"（读真数据、训练真模型、接真硬件）一律是占位，且界面上必须标得明明白白。**

| 维度 | 第一版（已实现） | 后续（占位 / 未来可扩展） |
|---|---|---|
| 数据 | 后端生成模拟 EEG | SEED `.mat` 真实数据 |
| 波形 | 代表通道 8 条实时滚动 | 全部 62 通道渲染（性能模式） |
| 特征 | 原始波形展示 + PSD 可视化 | DE 微分熵 |
| 模型 | 模拟分类器（mock_predict） | SVM → CNN → CNN-LSTM → Transformer |
| 通信 | REST + WebSocket 全通 | 无新增 |
| 评估 | 无（不需要） | 交叉验证评估真实模型 |
| 硬件 | 无 | 真实 EEG 设备采集 |

## 3. 前端页面与组件清单

### 3.1 页面

第一版**只有一个主页面**，没有多页路由。页面名：`EEG Emotion Recognition System`（脑电情绪识别演示系统）。

### 3.2 组件清单（第一版建议拆分，最小化）

> 依据文档 07 与「10.2 允许的最简结构」：只有当 `App.tsx` 明显过长（约超过 250 行）时才拆分组件。以下为**建议拆分**清单，最终以实际代码长度决定。

| 组件 | 职责 | 使用的主要 Ant Design 组件 |
|---|---|---|
| `App.tsx` | 主页面布局、全局状态、事件分发 | `Layout`、`Card`、`Divider` |
| `WaveformChart.tsx` | EEG 实时波形图 | ECharts 折线/滚动图 |
| `SpectrumChart.tsx` | PSD 频谱图 | ECharts 面积图 + 频段标记 |
| `ControlPanel.tsx` | 左侧五个卡片区域 | `Select`、`Button`、`Upload`、`Alert` |
| `EmotionCard.tsx` | 当前情绪结果卡片 | `Tag`、`Progress`、`Typography` |
| （可选）`HistoryTable.tsx` | 情绪历史表格 | `Table`、`Button` |
| `api.ts` | REST 请求 + WebSocket 连接 + 重连 | — |
| `types.ts` | TypeScript 类型定义 | — |

### 3.3 前端不做的清单

- 不做多页面 / 路由（不用 react-router）；
- 不用 Redux / Zustand / React Query / Axios / Tailwind / Styled Components / Sass / Less；
- 不做登录、注册、权限、国际化、主题切换；
- 不渲染 62 通道全部波形（仅占位选项）；
- 不自己生成任何"假数据"（数据必须来自后端）。

## 5. 不做清单（Won't Do / 本期明确不做）

1. 不做真实 SEED 数据解析；
2. 不训练任何真实机器学习模型；
3. 不接入 EEG 硬件；
4. 不做数据库持久化；
5. 不做用户账号与权限；
6. 不做云部署 / Docker / 微服务；
7. 不做多语言、主题切换、复杂路由；
8. 不做复杂的信号预处理（滤波组、ICA、伪迹去除、小波去噪）；
9. 不输出任何医疗结论；
10. 不做真实 62 通道全量渲染（性能模式为占位）。

## 6. 验收标准（Acceptance Criteria）

第一版是否完成，用下面这张"验收清单"判断。**每一项都必须能在演示现场真实验证。**

### 6.1 可运行性

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| A-01 | 后端能启动 | `uvicorn main:app --reload` 后 `http://localhost:8000/api/health` 返回 `{"status":"ok",...}` |
| A-02 | 前端能启动 | `npm run dev` 后 `http://localhost:5173` 正常显示页面 |
| A-03 | 前后端连通 | 页面顶部显示绿色「已连接」；断开后端后变为红色「未连接」 |
| A-04 | 波形滚动 | 主区 8 条通道波形随时间向左滚动，无需任何操作 |
| A-05 | 开始识别 | 点击「开始识别」，2–5 秒内结果卡片出现情绪与置信度 |
| A-06 | 暂停/继续 | 暂停时波形冻结，继续后恢复滚动 |
| A-07 | 停止识别 | 停止后显示「识别已停止」，结果不再更新 |
| A-08 | 重置演示 | 清除当前结果与历史，状态回到初始 |

### 6.2 界面与一致性

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| B-01 | 五区布局完整 | 顶部导航 / 左侧控制面板 / 主显示区 / 底部状态栏均存在 |
| B-02 | 占位标注清晰 | 所有占位功能（文件加载、DE、SVM/CNN/CNN-LSTM、62 通道性能模式）都有「后续接入/未实现」提示 |
| B-03 | 免责声明可见 | 结果卡片与 README 均有医疗免责声明 |
| B-04 | 历史记录 | 最近 10 条，支持清空 |
| B-05 | 日志有界 | 日志不超过约 50 条 |
| B-06 | 状态单一来源 | 前端所有"是否在识别/是否暂停"等状态来自后端接口/推送，无本地造假 |

### 6.3 诚实性

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| C-01 | 模拟来源标注 | 每个结果都标注 `当前来源：模拟分类器`，不冒充真实模型 |
| C-02 | 无虚假结果 | 文档/代码/界面中不存在编造的准确率、编造的 SEED 实验结果 |
| C-03 | 结果描述准确 | 文案写"模拟分类器输出"而非"系统准确识别了你的情绪" |

## 7. 风险与降级策略（Risk & Degradation）

| 风险 | 场景 | 降级策略 / 应对 |
|---|---|---|
| 没有 SEED 数据 | 真实 `.mat` 文件拿不到 | 第一版完全不依赖它；模拟数据自带，开箱即演示 |
| 没有真实模型 | 拿不到训练好的 SVM `.joblib` | 第一版用模拟分类器；SVM 只留接口 |
| 后端未启动 | 用户先开了前端 | 前端健康检查失败 → 顶部红点「未连接」，禁用「开始识别」，给出提示文案 |
| WebSocket 断线 | 后端重启或网络抖动 | 前端自动重连（指数退避），恢复后重新拉取 `/api/config` 与当前状态 |
| 性能压力 | 波形数据过大导致卡顿 | 只推 8 个代表通道 × 25 点/块；前端只保留最近 N 秒窗口 |
| 情绪结果跳变 | 模拟分类器输出不稳 | 后端按"模拟模式 + 小幅随机扰动"设计，结果 2–5 秒才更新一次，且置信度稳定在 0.60–0.95 |
| 老师追问"为什么是模拟的" | 答辩质疑真实性 | 直接说明：第一版验证"前端+后端+通信+可视化"整条链路，真实数据/模型是第二阶段；这本身是加分点（工程分层） |
| `.mat` 结构不统一 | SEED 不同版本字段名不同 | 文档明确注明：以实际文件说明为准，不做死假设（见文档 06 第 7 节） |

## 8. 一句话总结

> **第一版交付一个"模拟数据驱动、前后端分离、界面完整、诚实标注占位、无需真实设备即可演示"的脑电情绪识别 MVP；真实 SEED 数据与 SVM 模型作为第二阶段，接口已预留。**
